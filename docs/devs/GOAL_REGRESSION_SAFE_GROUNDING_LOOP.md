## 3. 핵심 아키텍처 원칙 (이 goal의 3대 신규 계약)

### 원칙 1 — 모든 fix는 단일 work-bridge 술어로 수렴 (결함 B 봉합)
표면별 단건 패치 금지. 맥락결속 fix는 **하나의 공유 술어** `_post_discusses_work_as_work(ctx, title) -> bool`로 구현한다(신규 LLM 호출 0, 기존 결정적 신호 재사용):
- 참 조건(분리합): 약칭사전/family_alias 검증 일치 ∨ `official_url_recoverable`(candidate_audit.py:1012)가 official_detail URL+post-side anchor 확인 ∨ decoder `anchor_type ∈ {title_mention, character_title_link, plot_mention}` ∨ work_consumption_markers(연재/완결/회차/작가/주인공/플랫폼) 동반.
- 거짓 가드: title이 본문 generic phrase의 substring일 뿐(`_is_genre_descriptor_surface` candidate_audit.py:941 / `_is_generic_topic_title` 역방향), 짧고 흔한 제목(고유성 낮음).
- **모든 승격/복구 진입점에 배선**(§7 목록 전부). 새 rescue 경로가 생겨도 이 술어를 우회 못 하도록 **계약 테스트**(아래 원칙 3)로 고정.

### 원칙 2 — 채택 게이트는 전수 회귀를 본다 (결함 C 봉합)
seed movement만으로 채택 금지. 모든 loop는 **3중 회귀축**을 통과해야 한다:
- **(a) Collateral 전수 스캔**: 동결 baseline full-run과 canary를 **공유 post_id 전체**로 비교 → `collateral_regression_count`(resolved→다른title, resolved→null on 비-queue post). 주의: `compare()`는 현재 seed_rows만 순회하므로 **플래그 토글로 안 되고 신규 루프를 추가**해야 한다 — baseline∩canary 전 post_id를 `analysis_identity()`로 식별 추출하고 `titles_match()`/`movement_status()`로 diff하는 collateral 패스를 신설(아래 §7 함수 재사용).
- **(b) 동결 골든셋**: positive(정답 resolved) + negative(no-work) 불변 집합을 **매 canary에 상시 포함**. 골든 회귀 1건이라도 = **hard FAIL**.
- **(c) Affected-module 테스트 선택**: `git diff --name-only`로 변경 파일 → 영향 테스트 모듈 매핑(rank 코드 건드리면 rank1/2/3 테스트 자동 포함). loop 종료 전 **전체 sweep** 1회. (IMP-300 재발 방지.)

### 원칙 3 — blind judge + 계약 테스트로 측정 신뢰성 확보
- **blind judge**: judge에 파이프라인 *결론*을 먼저 보여주지 말고(confirmation bias), 원천(title/body/comments/OCR/search_evidence)만 주고 독립 판정 → **사후 대조**. (현 스펙 약점 교정.)
- **결정적 replay**: canary는 동결 slang_db 스냅샷(read-only, `--slang-db off`) + 고정 parallel 모드 + ≥2회 재실행으로 분산 확인. production slang_db write-back 금지.
- **계약 테스트**: work-bridge 술어가 §7의 모든 승격 진입점에서 호출됨을 assert하는 테스트(진입점 우회 자동 검출).

## 5. Non-Negotiable Gates (Hermes 계약 + 신규)

기존 유지: ① run_integrity·targeted canary status·semantic quality·full-scan approval을 **모든 리포트에서 분리 보고**. ② runtime 완료 ≠ semantic 승인. ③ post_id/title-specific 하드코딩 금지(production code). ④ canary는 `--slang-db off`(production write-back 금지). ⑤ deterministic full-post aggregate와 native-web/queue aggregate **혼용 금지**. ⑥ Naver/Bing direct fallback은 degraded-provider로 label. ⑦ control sentinel(11694064 등) 미회귀, garbage_title_after=0, wrong_work 미회귀. ⑧ semantic_quality=REVIEW-LOCKED, full_scan_approval=false 유지.

**신규(이 goal의 핵심)**: ⑨ `collateral_regression_count`(전수) > 0 이고 그 회귀가 골든셋/판단정답 대조로 "정답 방향 변화"가 아니면 그 loop = **semantic NO-GO**(채택 금지·요수정). ⑩ 동결 골든셋 회귀 1건 = hard FAIL. ⑪ 변경 파일에 매핑되는 테스트 모듈 + 전체 sweep이 green 아니면 채택 금지. ⑫ 맥락결속 fix가 단일 work-bridge 술어 + 전 진입점 배선 + 계약 테스트 형태가 아니면(= 표면별 단건 패치면) 채택 금지.

> **단순 변화량 게이트 금지**: collateral diff는 반드시 **골든셋/판단정답과 대조**해 정당한 recall 개선(null→올바른 resolved)을 회귀로 오탐하지 않는다. 회귀 = "정답에서 멀어진 변화"만.

## 6. The Loop (Hermes 기반 + 회귀안전 보강)

### Phase A — Preflight + 측정 인프라 부트스트랩 (loop 1회만, 이후 갱신)
1. active queue/report Read. 직전 loop next_queue rows=0은 "최신 closure"로만 보고 main 재실행 금지.
2. **동결 baseline 고정**: 직전 large/full run 결과(예 `out/expert_result_20260620_165159_711176_completed_subset.json` 또는 최신 full)를 `out/<loop_root>/baseline/baseline_result.json`으로 read-only 복사. 이후 모든 collateral 비교의 분모.
3. **Regression Panel 구성(신규)**: baseline에서 **층화 추출**한 고정 패널을 `out/<loop_root>/panel/regression_panel.jsonl`로 동결 — (i) 6개 error class 각각의 양성(정답 resolved) + 음성(no-work) 대표, (ii) rank1/rank2/rank3 게이트가 보호하는 정당 해소 대표, (iii) 정당 약칭 recall 대표(이티알·마도서줍 류), (iv) survey 136 오류행. 한 번 만들면 **루프 내내 불변**(입력 분포 변동으로 게이트 시야가 줄지 않게).
4. **동결 골든셋**: `clean_canary_row()`(build_judge_seed_registry.py:351)로 정답누설 제거한 positive+negative 골든을 `out/<loop_root>/golden/golden_set.jsonl`로 동결.
5. live vLLM 모델 확인(`http://10.20.0.101:8000/v1/models`, stale 404 회피). git status 확인하되 무관한 사용자 변경 revert 금지.

### Phase B — Judge re-audit (blind) → taxonomy → queue
6. 신규 seed 모집단: survey 136행 + native-web non-ACCEPT residual + ACCEPT 샘플(회귀 감시용) + Regression Panel. `build_completed779_issue_index.py`/`build_judge_batches.py` 재사용.
7. **blind judge**: §3 원칙 3대로 파이프라인 결론 가린 채 원천+search_evidence만으로 독립 판정 → 사후 대조. 엔진 = Codex 5.5 native web(기본). verdict 스키마/taxonomy = LLM_JUDGE_ANALYSIS_SPEC §2-2/§3. failure_class를 survey 9-enum(generic_phrase_substring/homonym_cross_domain/batch_context_bleed/wrong_work_among_aliases/image_anchor_spurious/over_resolved_nonwork/slang_pollution/recall_miss/none)으로 태깅.
8. queue row에 `suspected_code_hook`·`proposed_next_fix`·`required_test`·`fix_axis`를 비어있지 않게 채운다. **fix_axis별로 묶어** 같은 work-bridge 술어로 수렴 가능한지 판단.

### Phase C — Diagnosis (단일 술어로 수렴)
9. Hermes Council fan-out(explorer/challenger, 승인권 없음; 모델 다양성=variance reduction). 각 row: observed signal/왜 null·noise/expected movement/**어느 work-bridge 조건이 빠졌나**/over-promotion risk/required test.
10. 같은 fix_axis의 다수 row가 단일 술어 보강으로 닫히는지 확인. **표면별 분기 추가 대신 술어 조건 추가**를 선호.

### Phase D — Implement (단일 술어 + 전 진입점 배선 + 계약 테스트)
11. 맥락결속 fix: `_post_discusses_work_as_work` 술어를 보강하고 §7 **모든 승격/복구 진입점**에 배선. 새 진입점 추가 금지(있으면 술어 경유 강제).
12. 동음이의(FIX-2)·slang decode 게이트(FIX-3)·랭커 분리(FIX-4)는 survey 보고서 §4 위치대로. slang은 `decode_verified is True` 인입 게이트 + `is_confirmable` 예외(저위험).
13. **계약 테스트 추가**: 술어가 전 진입점에서 호출됨을 assert(우회 자동 검출). post_id 핀 의존 최소화 — 입력 분포 불문 게이트 검증.

### Phase E — Targeted canary (결정적 replay)
14. canary 입력 = queue seed + Regression Panel + 골든셋 + control sentinel. text/url/comment vs image/OCR 분리. loop prefix로 네임스페이스(덮어쓰기 금지).
15. `expert_main.py` 실재 실행(`.venv312\Scripts\python.exe`): text `--server-type vllm --llm-endpoint http://10.20.0.101:8000 --reuse-shards-only --no-dashboard --slang-db off --parallel <min(input,36)>`; image는 `--vlm on --ocr on --require-vlm-ocr-for-images` 추가. **동결 slang_db 스냅샷 read-only**, **≥2회 재실행**으로 분산 확인. preflight 막히면 정확한 실패+resume 명령 기록(runtime 미검증 표기).

### Phase F — Compare (3중 회귀축)
16. **seed movement**: `compare_completed779_improvement.py`로 queue seed before/after(기존).
17. **collateral 전수 스캔(신규)**: 동결 baseline vs canary를 **공유 post_id 전체** 비교하는 신규 패스를 추가(compare()의 seed-only 순회로는 불가) → `collateral_regression_count`. `analysis_identity()`(:87)·`titles_match()`(:241)·`movement_status()`(:386) 재사용. 골든셋/판단정답 대조로 정당 변화 면제.
18. **골든셋 검증(신규)**: 골든 회귀 0 확인. 1건이라도 FAIL.
19. **테스트(신규 선택 방식)**: `git diff --name-only` → 영향 모듈 매핑(예 arbiter/decoder/agentic_pipeline 변경 시 test_title_lead_search_inferred_guard·test_agentic_pipeline_alias_contract·test_final_semantic_reread_gate·rank1/2/3 테스트 포함) + **전체 unittest sweep** 1회. `py_compile` + `git diff --check`.

### Phase G — Acceptance audit (확장 게이트)
20. row 이동이 candidate_preserved/unresolved_matchable/HOLD·human_review/strong-evidence resolved/no_generalizable_fix_left 인지. garbage_title_after=0, sentinel 미회귀, wrong_work 미회귀.
21. **§5 신규 게이트 ⑨⑩⑪⑫ 전부 통과** 확인. 하나라도 실패 = 그 loop semantic NO-GO → 패치 보류/수정.

### Phase H — Requeue / Docs / Continue
22. `build_reimprovement_queue()`(:699) + REIMPROVEMENT_STATUSES로 next queue. row-level rationale 필수. **collateral 회귀로 잡힌 신규 회귀행도 queue에 추가**.
23. Docs sync: `goal.md`(active contract), TODO/CHECKLIST/HISTORY/IMPROVEMENT_REGISTER/VERIFICATION_RESULTS. 4-게이트 분리 보고. **collateral_regression_count·골든 결과·affected-module 테스트 결과를 매 loop 기록**.
24. **Continue 조건**: next queue가 비었거나 모든 잔여 row가 HOLD/human_review/INFO_MISSING/unresolved_matchable/quarantine/no_generalizable_fix_left + rationale일 때만 정지. 아니면 같은 루프 반복.
