## 1차 전문가 회의

### 검색·평가 분과

현재 저장소에는 candidate ID+NIL, Brier/log-loss/ECE, AURC·risk-coverage, CAL/FROZEN readiness, paired readback 계약이 이미 있다. 가장 큰 결손은 평가식이 아니라 실제 retriever/reranker 비교와 source-backed gold다.

### lexicon·데이터 분과

중앙 Slang DB의 exact-pair fail-close와 42개 seed 격리는 유지해야 한다. 새 자료는 중앙 DB에 넣지 않고 `lexicon_candidate_ledger`, `work_alias_registry`, `community_lexicon`으로 분리한다.

각 claim에는 surface와 sense뿐 아니라 `lineage_root_id`, `parent_source_id`, `independence_group`, URL/locator, 작성·수정·수집 시각, content hash, parser profile, 권리 상태를 남긴다. 같은 목록의 백업·재인용은 여러 독립 vote로 세지 않는다.

### 시스템·MLOps 분과

llama.cpp 계열 현재 backend를 기준선으로 유지한다. vLLM/SGLang은 Linux/NVIDIA 환경에서 semantic 입력·prompt·tokenizer·snapshot을 고정한 offline shadow가 준비된 뒤에만 비교한다.

기존 manifest와 WAL이 정본이다. 외부 tracker·evaluator는 aggregate metric과 artifact reference를 받는 sink일 뿐 publication 상태를 결정하거나 원문을 보관하면 안 된다. backend 성능 A/B와 semantic A/B를 동시에 바꾸지 않는다.

### source claim

### A — 작품 매칭

```text
post_id / content_fingerprint / source_time
alias_surface
gold_class = WORK | NIL
gold_work_id = candidate_id | null
alias_relation
relation_to_post
competing_work_ids[]
official_evidence
community_evidence

inference_decision = ASSERT_WORK | ASSERT_NIL | ABSTAIN

reason_code
```

`gold_class`는 truth, `annotation_status`는 사람이 판정할 수 있었는지, `inference_decision`은 모델의 latent 결정, `publication_action`은 운영 조치다. search miss, backend 오류, incomplete producer, 근거 접근 실패는 `NIL`이 아니라 `UNAVAILABLE + ABSTAIN + HOLD`다.

### B — 커뮤니티 이해

```text
surface / sense_id
term_type / definition
community_scope / platform_scope
discourse_function
valid_from / valid_to
temporal_status = ACTIVE | STALE_REVIEW | RETIRED
sensitive / related_terms
source_claim_ids[]
```

A의 alias claim은 `OBSERVED → CORROBORATED → TITLE_VERIFIED → HUMAN_CONFIRMED`, B의 sense claim은 `OBSERVED → CORROBORATED → CONTEXT_VERIFIED → HUMAN_CONFIRMED`로 올린다. `CONFLICT`와 `STALE_REVIEW`는 승격을 멈추는 재검토 상태이고, `REJECTED`와 사람이 확인한 `RETIRED`만 종착 상태다. 낮은 빈도나 단순 미관측만으로 `RETIRED`로 바꾸지 않는다.

## P0~P3 실행 계획

### P0 — 계약·source pilot

목표는 모델 성능이 아니라 source 구조와 gold 작성 가능성을 검증하는 것이다.

- source profile별 claim 10개, 총 40개와 실제 문맥 20개를 사람이 확인한다.
- URL·locator·시각·author·content hash·parser profile·lineage 필드 존재율 100%를 요구한다. 익명·삭제·플랫폼 제한으로 값이 없으면 `UNKNOWN_WITH_REASON`을 기록하며, content hash·collected_at·parser profile은 실제 값이 필수다.
- 규칙 parser는 span·방향·locator만 추출하고, 미지 형식은 누락시키지 않고 generic queue로 보낸다.
- LLM repair는 원문 span hash에 묶인 `repair_existing`/`ABSTAIN`만 반환한다.
- 기존 WAL·publication·Slang DB write는 변경하지 않는다.
- adapter schema, optional import guard, hash binding, rollback receipt를 먼저 테스트한다.

Exit: P0 fixture의 item split·방향·lineage가 수동 판정과 일치하고 중앙 DB mutation이 0이다.
Stop: source mismatch, 필수 값 누락 또는 이유 없는 UNKNOWN, independence 불명 상태의 승격, LLM 신규 문자열 생성, 기존 publication 경로 변경, core dependency 증가.

#### 6차 actual authority tranche 설계 재회의

데이터·계약과 runtime 호환성 전문가의 독립 검토를 합쳐 다음 구현 경계를 채택했다. 현재 필드의 opaque SHA와 self-hash는 내용 무결성만 보여 주며 owner authority를 증명하지 않는다. 따라서 caller가 준 `authority=true`나 run directory 안에서 함께 만든 policy/hash로 gate를 열지 않는다. 실제 authority의 시작점은 run root 밖에 사전 provision되고 사용자가 고정한 owner trust anchor와 detached authorization이어야 한다. 무의존 최소 구현은 stdlib HMAC-SHA256이지만 key를 validator가 만들거나 run root에서 읽어서는 안 되며, 향후 비대칭 서명으로 교체 가능한 domain-separated payload를 사용한다.

권한 artifact DAG는 `외부 owner anchor → capture/rights/guideline/sampling policy → 사전 launch manifest·watch pre-snapshot → capture → rights assessment → parser/generic queue → candidate registry → annotation subject/reviewer assignment → novelty → annotation segment/checkpoint/head → runtime watch post-snapshot → final actual pilot manifest → validation receipt`의 단방향으로 고정한다. `p0_actual_authority_contract.py`는 기존 foundation과 분리된 stdlib-only 모듈로 만들고 ledger·Slang·recovery·Pyserini writer/runtime 모듈을 import하지 않는다. final validator만 fixed-directory artifact를 직접 재읽어 authority flag를 계산하며 manifest의 자기진술 flag는 금지한다.

append-only는 현재 파일의 local hash-chain만으로 승인하지 않는다. 사전에 고정한 genesis/predecessor checkpoint, byte-exact prefix, 새 canonical segment, 전역 `(target_type,target_id)→single journal/head` map을 모두 재검증한다. 비간섭은 중앙 Slang DB·publication WAL/journal·checkpoint/result/recovery의 파일 SHA뿐 아니라 watched directory membership의 생성·삭제·교체도 비교한다. before/after가 같아도 실행 중 썼다가 복구한 행위는 잡지 못하므로 OS write-deny sandbox 증거가 없으면 `terminal_membership_projection_equal`만 주장하고 `runtime_noninterference_verified=false`를 유지한다.

### P1 — silver ledger와 single-curator gold-lite

단일 운영자가 감당할 수 있는 최초 자료를 만든다.

- gold-lite: DEV 50, CAL 30, FROZEN 70, challenge 30.

- 20%는 최소 7일 뒤 다시 판정해 intra-curator disagreement를 측정한다. 이를 2인 agreement로 부르지 않는다.
- DEV/CAL/FROZEN 사이 source·content·work·alias family·lineage 중복을 0으로 만든다.

- 5개: 양성·음성 sentinel control

Exit: candidate recall과 parser 지표의 분모가 생기고 `UNJUDGED/UNAVAILABLE`이 별도 회계된다.
Stop: weak label의 FROZEN 유입, lineage 중복 vote, gold split 누수, 중앙 DB mutation.

### P2 — 검색·reranking·role·NIL component A/B

한 번에 한 계층만 바꾼다.

1. `A0`: 기존 pipeline 기준선
2. `A1.exact`: exact alias/official ID
3. `A1.bm25`: BM25 추가
4. `A1.dense`: dense 추가
5. `A1.union`: canonical dedupe 뒤 후보 합집합
6. `A1.rrf`: 같은 후보원에 RRF baseline
7. `A2.rerank`: 고정 candidate set의 immutable-ID reranker
8. `A2.role`: 충분한 relation label이 생긴 뒤 별도 role head
9. `A3.evidence`: 작품 실재와 게시글 주작품 근거 receipt 분리
10. `A4.nil-calibration`: NIL cause·UNAVAILABLE·HOLD 분리와 calibrated abstention
11. `A5.combined`: A1~A4를 같은 frozen input에서 조합

상위 arm `A0~A5`는 기존 연구의 namespace를 유지하고 점 뒤 suffix만 component sub-arm으로 사용한다. manifest에는 상위 arm과 sub-arm을 별도 필드로 기록한다.

후보 단계에서는 `Recall@1/5/10/20`, oracle union recall, lane별 unique-gold, dedupe율, candidate miss를 본다. `candidate_recall_operational`은 모든 eligible `JUDGED+WORK`를 분모로 하며 incomplete/unavailable을 miss로 포함한다. complete-only recall은 진단값으로만 둔다. 선택 단계에서는 gold-present accuracy/MRR, wrong-work, role macro-F1/confusion을 보고, end-to-end top-label accuracy와 분리한다. NIL 단계에서는 NIL precision/recall, unavailable, abstain, coverage, selective risk를 각각의 분모와 함께 본다. UNJUDGED/UNAVAILABLE을 제외하면 annotation coverage와 worst-case sensitivity bound를 병기한다.

reranker는 새 후보를 생성하지 않는다. 장애 시 이전 순위를 조용히 쓰지 않고 `RERANK_UNAVAILABLE`로 HOLD한다. role head와 retrieval engine은 semantic A/B 도중 고정한다.

Exit: 구조·metric이 계산 가능하고 critical regression이 0인 component shadow다. 기존 연구의 권고 A는 candidate recall lower `≥.95`, NIL precision/recall lower `≥.90`, coverage `≥.10`, selective-risk upper `≤.05`지만 모두 `ACTUAL_POLICY_PENDING` 제안값이다. 소유자 확정 전에는 숫자 gate를 통과했다고 쓰지 않으며 결과를 본 뒤 값을 바꾸지 않는다.
Stop: false publish 1건, search failure→NIL, 후보 provenance 누락, producer가 불완전한데 non-null headline 생성, 새 wrong-work.

### P3 — calibration·paired end-to-end·제한 운영

gold-lite에서 구조를 닫은 뒤 production 주장을 위한 자료를 확장한다.

- 같은 input bytes/order, prompt, retrieval snapshot, seed를 사용한 fresh BEFORE/AFTER paired shadow를 실행한다.

- Brier, log loss, ECE, AURC, selective risk, coverage, NIL precision/recall, correct-title recovery, unsafe/wrong-work, calls/tokens/p50/p95를 같이 보고한다.

unsafe auto-publish 0건의 one-sided 95% 상한을 1% 아래로 주장하려면 독립 auto-publish decision이 최소 299개 필요하다. FROZEN 200행 전체가 아니라 실제 auto-publish 분모로 계산한다. FROZEN에서 부족한 decision은 **동일하게 사전 등록된 모델·retriever·policy를 한 번도 조정하지 않은 채** 별도 `TIME_LATER_RANDOM/CANARY_SAFETY_HOLDOUT`을 계속 수집해 채운다. target population·policy revision·snapshot regime이 같고 post/work/lineage가 겹치지 않는 decision만 합산하며, 조건이 다르면 별도 구간으로 보고한다. 필요한 원시 행 수는 FROZEN 관측 coverage 뒤 `ceil((299-current_eligible_publish)/conservative_coverage_lower_bound)`로 사전 산정한다. 299건 미만이거나 single-curator 자료뿐이면 semantic production은 계속 `NO-GO`다.

오류 0과 독립 Bernoulli라는 제한 아래 산식상 최소는 candidate recall lower 0.95에 eligible WORK 59/59, selective-risk upper 0.05에 covered 59/59, two-sided NIL lower 0.90에 predicted-NIL 36/36과 true-NIL 36/36이다. 이는 승인 숫자가 아니라 데이터 계획을 위한 하한이다. 오류가 있거나 cluster 상관이 있으면 exact CI·simulation으로 더 큰 표본을 사전 산정하며, actual policy 확정 전에는 통과 판정을 하지 않는다.

Exit: 소유자가 결과 전에 등록한 actual numerical policy에 따라 paired CI 비열화 없음, critical unsafe/wrong-work 0, required search unrecovered 0, HOLD sentinel 100%, stable control loss 0, coverage 하락으로 안전성을 세탁하지 않음. 이것은 shadow evidence 완료 조건이며 자동 운영 승인 조건이 아니다. 통과 뒤에도 `REVIEW-LOCKED`, `full_scan_approval=false`를 유지하고 별도 owner 승인을 받는다.

## active learning·시간성 계획

active learning은 P1 gold-lite와 prevalence-stratified random anchor 이후에만 시작한다. batch 구성은 다음으로 사전 고정한다.

- 25%: 층화 무작위 탐색
- 나머지: uncertainty+diversity+expected harm+novelty
- 필수 quota: source, platform, A/B term type, time bucket, wrong-work, NIL, OCR, sensitive, challenge

선택된 행은 DEV 개선에는 쓸 수 있으나 FROZEN holdout에 넣지 않는다. model/retriever가 바뀌면 selection policy revision도 manifest에 남긴다.

temporal snapshot에는 timestamp뿐 아니라 source response bytes/hash, canonical URL, retrieval index hash, analyzer/tokenizer, crawl/search configuration, model/runtime revision을 포함한다. live URL revalidation은 snapshot 교체가 아니라 별도 관측 event다.

## adapter·dependency·rollback 계약

권장 경계는 다음과 같다.

- `ModelServerAdapter`: messages/sampling/schema 요청, 응답·usage·timing·runtime fingerprint만 반환
- `RetrievalAdapter`: immutable candidate ID와 canonical URL·snapshot hash·rank·retriever version·degraded reason 반환
- `RerankerAdapter`: 기존 후보의 점수·순서만 변경
- `EvaluatorAdapter`: FROZEN 결과에서 metric event/CI 생성, publication WAL 쓰기 금지
- `TrackerSinkAdapter`: aggregate metric·artifact reference만 export, 원문·검색 content·secret 금지
- `TemporalSnapshotAdapter`: URL·response bytes/hash·index hash·request config 결속

production core path는 신규 direct dependency 0개를 원칙으로 한다. Pyserini, sentence-transformers/cross-encoder, Snorkel, vLLM/SGLang, Ragas/DeepEval, MLflow는 optional extra 또는 별도 virtual environment에 둔다. optional package가 없어도 기존 import·offline regression이 동작해야 한다.

manifest 필드는 additive하게만 늘린다.

```text
experiment_id / pair_id / arm
backend / endpoint / model_revision / tokenizer_revision / quantization
prompt_version / retrieval_version / reranker_version
temporal_snapshot_sha256 / adapter_release_fingerprint
requested_parallel / effective_parallel / dashboard_enabled / seed
publication_mode = SHADOW | PRODUCTION
run_spec_sha256
```

rollback은 feature flag로 이전 adapter/config로 돌아가되 기존 publication WAL을 수정하지 않는다. 새 artifact는 보존하고 `rolled_back_from`, `rollback_reason`, `rollback_at` receipt를 추가한다. backend 장애 때 다른 모델로 자동 전환하지 않고 HOLD하며, baseline fresh replay와 readback을 다시 수행한다.
