# Loop627 adjudicated re-baseline adjusted-drift gate wiring

Loop627은 새 runtime replay나 full375를 실행하지 않았다. 목적은 사용자 지시대로 `true triage 57`과 intended recovery 전 행 판결이 끝난 뒤, 판결된 Loop620/Loop621 결과를 새 baseline으로 재동결하고 이후 collateral을 `raw vs 2026-06-26`이 아니라 `adjusted_drift`로 재는 gate 계약을 코드와 문서에 고정하는 것이다.

## 변경

- `tools/compare_projection_collateral.py`
  - `--baseline-mode adjudicated_rebaseline` 옵션을 추가했다.
  - 이 모드에서 `baseline_mode=adjudicated_rebaseline`, `collateral_measure=adjusted_drift`, `adjusted_drift_count`를 산출한다.
  - 2026-06-26 bootstrap 대비 raw는 `historical_raw_collateral_regression_count` 또는 별도 `historical_raw_compare` 참고값으로 남기고, 완료 blocker로 쓰지 않는다.

- `tools/evaluate_always_on_regression_gates.py`
  - `baseline_mode=adjudicated_rebaseline` 또는 `collateral_measure=adjusted_drift`를 보면 `gate_metric=adjusted_drift_count`로 collateral gate를 평가한다.
  - `historical_raw_collateral_regression_count > 0`이어도 `adjusted_drift_count=0`, runtime complete, search/publication gate clean이면 raw 때문에 gate를 막지 않는다.
  - `full_scan_approval=false`는 유지한다. Collateral GO는 full_scan approval이 아니라 full_scan 경로 진입 조건이다.

## 계약 문서

- `docs/devs/ADJUDICATED_REBASELINE_CONTRACT.md`
  - 도구 필드 계약을 추가했다.
  - 완료 gate는 raw가 아니라 adjusted 기준임을 명시했다.
  - 6/26 baseline 대비 raw는 정당 제거/의도 복구 때문에 영구히 0이 아닐 수 있으므로 역사 설명용으로만 남긴다.
