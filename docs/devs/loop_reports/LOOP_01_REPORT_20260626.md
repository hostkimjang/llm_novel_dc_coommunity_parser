## 3) 연구·근본원인 분석

- `136`건 survey error와 이번 `1933`건 aggregate가 같은 방향을 가리킨다. 문제는 단일 "제목 추출 실패"가 아니라, work-discussion 판정, 후보 보존, public promotion, source URL evidence, slang 저장 경계가 한 predicate에 섞이는 구조다.
- `reason_evidence_mismatch=120`은 runtime 구조상 resolved처럼 보이는 row와 evidence/reason 문구가 서로 다른 의미를 내는 케이스다. 이는 semantic approval 전에 output consistency lint 또는 final state/reason sync가 필요하다는 신호다.
- `slang_db_review=92`는 `slang_db`를 무작정 확장하면 common-word pollution으로 돌아올 수 있음을 보여준다. Phase 2에서는 slang store/read-only guard를 분리해야 한다.
- `boundary_needs_human=25`와 `ocr_only_title=25`는 자동 promotion이 아니라 candidate/HOLD/human_review가 맞는 경계다. 특히 image anchor 기반 추론은 title evidence와 work-discussion evidence를 분리해야 한다.
- `wrong_work=7`은 수는 작지만 high severity가 포함되어 있다. 이 축은 native web title existence/page-title match 확인 없이 통과시키면 안 된다.
