# Loop360 background watchdog hardening

## 요약

- Loop359 background 런은 검색 launch health가 아니라 LLM watchdog pause에서 멈췄다.
- full375, bounded1200, golden18, safe-loss first manifest는 모두 result/checkpoint `0/0/0/0` 상태라 approval 근거가 아니다.
- safe-loss first log는 `llm-watchdog`가 `터미널에 y를 입력하거나 웹 대시보드에서 재개하세요`를 출력한 뒤 멈췄다.
- `tools/safe_loss_flip_rate_probe.py`가 독립 probe command에 `--llm-suspend-on-anomaly off --llm-suspend-threshold 0`를 자동 포함하도록 고쳤다.
- `tools/run_independent_plan.py`도 기본 환경에 `LLM_SUSPEND_ON_SERVER_ANOMALY=0`, `LLM_SUSPEND_FAILURE_THRESHOLD=0`를 넣어 오래된 plan도 runner 경유 시 interactive pause를 피한다.

## 변경

- `tools/safe_loss_flip_rate_probe.py`
  - background probe command에 interactive LLM suspend prompt 비활성화 옵션을 기본 추가한다.
  - plan manifest에 `noninteractive_watchdog_contract`를 기록한다.
- `tools/run_independent_plan.py`
  - runner subprocess 환경에 LLM suspend 비활성화 기본값을 추가한다.
  - subprocess stdout을 명시적으로 닫아 테스트 ResourceWarning을 제거했다.
- `tests/test_safe_loss_flip_rate_probe.py`, `tests/test_run_independent_plan.py`
  - N5 command argv와 runner 환경 기본값 계약을 검증한다.
