## 3) 연구/근본원인 분석

초기 근본 원인은 alias recall이 제목 token을 그대로 플랫폼 검색어로 쓰면서 한국어 조사 결합 표면을 alias로 복원하지 못한 점이다. 또한 alias-only 검색 결과는 tag collision 위험이 있으므로, 단순히 `#alias`가 보인다고 promotion하면 `랫따싶` 계열처럼 공유 tag 오귀속이 재발한다.

첫 canary 실패의 추가 원인은 curated abbreviation registry와 ordering이었다. `괴라리 -> 괴담에 휘말렸다`는 이미 registry에 있었지만 `니생들 -> 니들 생각 다 들린다`는 없었고, post title에 `니생들이랑 김괴라리`가 함께 있을 때 secondary alias가 최종 후보를 이겼다. 따라서 follow-up fix는 post_id hardcoding이 아니라 curated alias registry와 surface-order precedence를 보강하는 방향으로 제한했다.

이번 fix는 세 조건을 결합한다.

- Search materialization: `이랑`, `이`, `가`, `은`, `는`, `을`, `를` 등 suffix를 벗긴 stem을 먼저 검색한다.
- Promotion guard: official title 단어 초성의 tight subsequence 또는 첫 단어 prefix + 마지막 단어 suffix로 alias가 설명될 때만 alias-only official-detail result를 허용한다.
- Known-abbreviation precedence: curated alias가 여러 개 보이면 post-local occurrence order를 기준으로 primary surface를 선택한다.

`판초법사 -> 판초우의의 마법사` 형태도 같은 술어가 설명할 수 있지만, 실제 row-level recovery는 별도 canary 전까지 승인하지 않는다. `랫따싶` tag-only collision은 negative test로 계속 차단한다.
