# Loop509 shared gate repair28 재회계 및 repair27 replay 준비 보고

## 회차 요약

Loop509는 Loop508 targeted runtime replay 결과를 Loop502 `repair28` 큐에 교차 반영한 회차다. Loop508은 publication contract stale 7건을 runtime으로 검증했지만, repair28 내부에서는 `11684372` 1건만 직접 덮었다. 따라서 repair queue는 `28 -> 27`로만 줄고, residual105와 full375 collateral gate는 그대로 열린다.

이번 회차에서는 남은 27건을 단건 반복이 아니라 N건 batch replay로 검증할 수 있도록 입력과 run plan을 생성했다. 실행 계획은 사용자 지시대로 `--parallel 16`을 요청하고 standalone dashboard `http://127.0.0.1:8080`에 붙는 `tools.run_independent_plan` 경로를 사용한다.

## 연구·근본원인 분석

- Loop508의 `GO`는 stale static artifact가 current runtime output에서 재현되지 않는다는 계약 증거다. repair28 전체가 해소됐다는 뜻이 아니다.
- `11684372`은 image/OCR work-title 후보가 미검증 official support 조건에서 candidate_only hard-hold로 남는지 확인한 사례다. 이는 image/alias anchor lane의 우회 publish를 막는 증거다.
- 나머지 27건은 아직 같은 수리 계약이 실제 packet batch에서 title publish/candidate preservation/search-blind 태그를 단조적으로 유지하는지 확인하지 못했다.
