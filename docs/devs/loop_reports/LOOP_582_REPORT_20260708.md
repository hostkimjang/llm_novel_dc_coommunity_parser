# Loop582 residual P0 contract queue와 dashboard 실행 계약

Loop582는 Loop581 P0 residual `19`건을 새 runtime 없이 계약/검토 queue로 재분해한 회차다. 테스트런 진행상황 확인 요구는 `--parallel 16`, 웹 dashboard 기본 ON, `--no-dashboard` 금지 계약으로 유지했고, 현재 standalone dashboard는 `http://127.0.0.1:8080`에서 `ok=true / standalone=true / pid=9320`로 응답한다.

## 요약

- 새 runtime replay, bounded run, full375 대형 runtime run은 실행하지 않았다.
- `tools/build_residual_p0_contract_queue.py`를 추가해 P0 residual을 shared-gate, candidate-set, source-native/blind 검토 bucket으로 분리했다.
- Loop582 contract queue는 rows `19`, validation issue `0`, runtime replay allowed `0`이다.
- Shared-gate clean lane은 `6`건이지만 공식 detail URL까지 갖춘 publish contract 후보는 `1`건뿐이다.
- Shared-gate URL 보강 hold는 `5`건, native-web/image 사전 검토는 `1`건, no-publish guard 사전 검토는 `1`건이다.
- Candidate-set rebuild는 `4`건 모두 publish 전 후보셋 재구성이 필요하고 runtime replay allowed `0`이다.
- Source-native/blind INFO_MISSING review는 `7`건이며 판정 전 hard-hold 완화 대상이 아니다.
- `tools/build_ordinary_restore_contract_plan.py`는 action batch의 `dispatch_lane`을 직접 읽고, 공식 detail URL 없는 restore 후보를 `official_support_missing_restore_hold_contract_case`로 보존한다.

- Candidate-set plan은 rows `4`, action `candidate_set_rebuild_required_before_publish 4`, promotion decision `reject 4`, runtime allowed `0`이다.
