# Loop370 search degraded-zero 반복 억제 계약 보고서

## 범위

- 신규 대형 런과 동일 parent packet 재실행은 계속 동결했다.
- Loop369에서 반복 확인된 `site:novelpia.com/novel "아생갤"` 같은 degraded 0건 쿼리의 즉시 재호출을 줄이는 코드 계약만 추가했다.
- R1 하드코딩 cue 리스트, 작품별 예외, golden expected, promotion hard-hold 정책은 변경하지 않았다.

## 변경

- `src/llm_batch/agentic_pipeline.py`
  - degraded/possible throttle + raw 0 + accepted 0 + language filtered 0인 쿼리를 정상 `_search_cache`에 넣지 않는 기존 정책은 유지했다.
  - 대신 별도 in-process suppression map을 추가했다.
  - 기본 TTL은 `PIPELINE_SEARCH_DEGRADED_ZERO_SUPPRESS_TTL_SECONDS=180`초이며 `0`이면 비활성화된다.
  - suppression hit는 MCP를 다시 호출하지 않고 `suppressed_degraded_zero=true` 메타를 남긴다.
  - 성공 결과나 안정적인 true zero cache가 생기면 suppression entry를 제거한다.
- `src/llm_batch/experts/orchestrator.py`
  - `degraded_zero_suppressed_total` 통계를 추가했다.
  - suppressed hit는 cache hit로 세지 않고, degraded zero 상태는 유지해 검색 blind 조건을 숨기지 않는다.
- `src/llm_batch/experts/utils.py`
  - 전문가 입력용 search aggregation summary에 suppressed 수를 노출했다.
- `tests/test_search_degraded_zero_suppression.py`
  - 같은 degraded-zero 쿼리의 MCP 재호출 억제, TTL 0 비활성화, 별도 통계 집계를 계약으로 고정했다.
