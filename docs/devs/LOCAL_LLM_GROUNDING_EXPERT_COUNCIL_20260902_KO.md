### 표본과 CI

- gold-lite `DEV 50 / CAL 30 / FROZEN 70 / challenge 30`은 구조 pilot floor다.
- 실제 P3의 `DEV 120 / CAL 120 / FROZEN 200`도 일반 packet의 provisional floor이며 safety claim을 자동 보장하지 않는다.
- 오류 0의 독립 Bernoulli라는 제한 아래 candidate recall lower 0.95에는 WORK 59/59, selective-risk upper 0.05에는 covered 59/59, two-sided NIL lower 0.90에는 predicted-NIL 36/36과 true-NIL 36/36이 각각 필요하다.
- 실제 수치는 [NIST exact binomial interval](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)로 다시 계산한다. 오류가 있거나 cluster가 있으면 더 큰 표본이 필요하다.
- paired delta는 `independence_group` cluster bootstrap으로 계산한다. 실제 FROZEN은 구조적 최소 group 30개·2,000회 미만이면 `NOT_ESTIMABLE`로 닫는다.
- P3 confirmatory primary comparison은 사전 고정한 `A5 vs A0` 하나로 좁히거나 multiplicity policy를 등록한다.

## P0~P3 실행 합의

### P0 — 계약·측정 정합성

Entry: target population, canonical universe, snapshot regime, schema version, write OFF를 고정한다.

- source profile 4종×10 claim과 실제 context 20개로 구조만 검증한다.
- source lineage, canonical/near-duplicate receipt, rights/retention, response/index/model/runtime fingerprint를 설계한다.
- truth·annotation·inference·publication 네 축을 분리한다.
- 전체행/non-abstain point estimate와 CI 분모를 맞춘다.
- publication/WAL/Slang DB mutation은 0이어야 한다.

Exit: 필수 provenance 실제값·결측 사유·lineage review 100%, generic fallback 수용, 중앙 write 0.
Stop: lineage unknown을 독립 vote로 사용, snapshot/hash mismatch, LLM 신규 문자열, production/core dependency 변경.

### P1 — gold-lite·baseline

- canonical JSONL ledger, blinded 7일 재판독, split leakage validator를 만든다.
- 20% 재판독은 이전 라벨을 숨기고 stratified random으로 뽑는다.
- Pyserini BM25, exact, dense의 lane별 recall과 oracle union recall을 측정한다.
- Snorkel/Cleanlab은 review priority만 만들고 FROZEN label을 변경하지 않는다.

### P2 — component shadow

- `A0 → A1 retrieval → A2 rerank/role → A3 evidence → A4 NIL/calibration → A5 combined` 순서를 유지한다.
- operational/complete-only recall, gold-present selection, end-to-end, NIL confusion, native/matched coverage-risk를 모두 분모와 함께 출력한다.
- wrong-work·unsafe publish 1건, search failure→NIL, incomplete 분모 제외가 발생하면 즉시 중단한다.

### P3 — confirmatory shadow·제한 운영

- owner-signed numerical policy SHA가 FROZEN 접근 전에 존재해야 한다.
- 2인 blind annotation+adjudication, 동일 input/snapshot/model/prompt/threshold의 A5 vs A0 paired run을 수행한다.
- independent auto-publish 299건 미만이면 `<1% unsafe`를 주장하지 않는다.
- 통과해도 상태는 `SHADOW_EVIDENCE_GO / REVIEW-LOCKED / full_scan_approval=false`이며 별도 owner 승인이 필요하다.
